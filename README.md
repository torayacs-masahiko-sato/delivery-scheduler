# 納品スケジューラー

営業チーム向け 納品スケジュール管理システム。
案件登録 → 候補日（仮スケジュール）調整 → 日程確定 → 納品 までを一元管理し、各ステップをメールで自動通知します。

**完全無料構成：Render.com（無料 Web Service） + Supabase（無料 PostgreSQL）**
**スマホ対応**：営業・管理者ともに外出先での操作を想定したレスポンシブ UI（ライト／ダークモード切替対応）

- **リポジトリ**: `masa31457131/delivery-scheduler`
- **本番URL**: https://delivery-scheduler-c4cd.onrender.com

> 営業は自分が担当営業として登録された案件のみ閲覧・操作できます（ダッシュボードの候補日待ち／仮スケ設定済／確定済み／キャンセルの全タブで自分の案件のみ表示）。

### ステータスフロー

```
候補日待ち(pending) → 仮スケ設定済み(scheduled) → 日程確定(confirmed) → 納品済み(delivered)
                                    ↓ いつでも
                                キャンセル(cancelled)
```

- 仮スケジュール（候補日）設定から **10営業日** 経過すると自動的にキャンセルされます（前日に警告メール、当日にキャンセル通知メールを自動送信。サーバー内で1時間毎にチェックする内蔵バッチのため、外部cronの設定は不要）。

## 2. 主な機能

### 案件・候補日管理
- 案件ID自動採番（`DS-YYYYMM-NNNN` 形式、月ごと連番）
- 案件登録時に希望候補日数（1〜3日）・納品方法（リモート／現地訪問）・備考（必須・50文字以内）を入力
- **管理者の案件情報編集**（全ステータス・キャンセル済みを除く）：案件詳細の「✏️ 編集」から、顧客名・案件内容・担当営業・納品方法・希望候補日数（候補日待ち・仮スケ設定済みのみ、登録済み候補日数以上）・備考を変更。確定済み案件は確定日時も変更でき、任意で関係者へ「日程変更」メール（テンプレート `schedule_changed`）を送信。入力 → 変更内容の確認（変更前→変更後）→ 保存の2段階
- **メッセージ（チャット）**：候補日待ち・仮スケ設定済み・確定済み・納品済み・キャンセル済みのどの状態でも、担当営業・依頼した営業・管理者がやり取りでき、過去の履歴をすべて表示。案件詳細上部の「💬 メッセージ（件数）」でメッセージ欄へ移動
- **依頼した営業（`requested_by`）**：日程確定時に候補日の営業メンバーへ担当営業が引き継がれても、案件を依頼した営業は引き続き案件・メッセージを閲覧・操作できる（既存案件は反映時点の担当営業を依頼者として補完）
- **関連URL（複数）**：案件ごとにURLを最大10件登録でき、それぞれにコメント（例：契約場所、納品場所、顧客情報。30文字以内・任意）を付けられる。登録画面・確認画面・案件詳細に表示し、詳細画面の「編集」から追加・削除・修正が可能（担当営業・管理者）。旧「顧客情報URL」（1件）は起動時に自動でコメント「顧客情報」付きの1件目として引き継ぐ
- 登録前に「登録内容の確認画面」を表示。問題なければ「この内容で登録する」、修正が必要なら「修正する」で入力画面に戻れます（入力内容は保持）
- 管理者が候補日を新規追加する際も確認画面を表示（日程・時刻・営業・CS部員を確認 → 「この内容で登録する」／「修正する」で入力に戻る）。候補日の編集は従来どおり直接保存
- 「候補日の設定完了」押下時も確認画面を表示（全候補日・営業・CS部員・通知先を一覧表示）。候補日が希望日数より少ない場合は、同じ画面で不足理由を入力
- 候補日ごとに **営業メンバー・CS担当者（1〜2名）をリストから個別に割り当て**（検索・エリア別グループ表示付きピッカー）
- ダブルブッキング防止：同一エリア・同日時に営業が重複していないかを候補日登録時に自動チェック
- 候補日から日程を確定すると、その候補日に紐づく営業メンバー・CS担当者が案件の正式な担当として引き継がれる
- 確定済み案件のCS担当者は管理者がいつでも変更可能（旧・新どちらのCS担当者にも変更通知メールが届く）
- 一括削除・選択削除（管理者、所有権チェック付き）
- 自動キャンセル：「候補日の設定完了」から10営業日（土日除く・祝日は考慮しない）で未確定の案件を自動キャンセル。9営業日目に事前警告メールを1回だけ送信。日付は日本時間で判定（サーバー休止中に警告日を過ぎた場合も起動後に1回送信）
  - 2026-11 修正前は起点日時が保存されておらず自動キャンセルが動いていなかった。修正版の反映時点で仮スケ設定済みだった案件は、**反映日を起点**に10営業日でキャンセル対象になる
- 「候補日の設定完了」時に入力した不足理由が保存されるよう修正（以前は保存されていなかった）

### 予定不可日・エリア管理
- 東京／大阪のエリアごとに、営業が候補日を提案できない期間を管理者が設定可能

### メール通知
- Gmail API（OAuth2）でメール送信。各通知には **案件をワンタップで直接開けるボタン付きリンク**（`https://delivery-scheduler-c4cd.onrender.com/?p=案件ID`）を掲載。ログインしていない場合はログイン後に自動でその案件の詳細画面が開く
- 通知タイミング：新規依頼／候補日設定完了／日程確定／キャンセル／リマインド／自動キャンセル警告・通知／CS担当変更
- 文面は管理者設定画面から自由にカスタマイズ可能（差し込み変数対応）
- 送信プロバイダはGmail API（推奨）／Gmail SMTP／Resendから選択式（アプリ内設定で切替可能）

### UI/UX
- liquid glass / Bento デザイン（`backdrop-filter: blur()`、floating glass pill ボトムナビ）
- ライトモード／ダークモード切替（トップバーから全ロール共通で切替可能、端末に保存）
- スマホ幅（〜420px）向けレスポンシブ調整

### セキュリティ
- パスワードは bcrypt でハッシュ化（既存の平文パスワードは自動移行）
- 全 Supabase テーブルに RLS（Row Level Security）を適用
- **ログイン必須のAPI**：ログイン後に発行される署名付きトークン（12時間有効）がないと `/api` は利用不可（疎通確認用 `/api/health` のみ公開）。管理者専用の操作（管理者・メンバー管理、メール設定、予定不可日の変更など）はサーバー側で管理者のみに制限
- **多要素認証（TOTP）**：Google Authenticator / Microsoft Authenticator 等の6桁コードによる2段階目の認証
  - 管理者は必須（初回ログイン時にQR読み取りで設定）／営業・CS部員は任意（ヘッダーの 🔐 から設定・解除）
  - バックアップコード10個（各1回のみ有効）を発行。スマホ紛失時は、バックアップコードでログイン、または他の管理者が「メンバー」画面から **リセット**
  - 認証用シークレットはAES-256-GCMで暗号化して保存／同じコードの使い回しは拒否
  - ID・パスワード・認証コードのいずれかを5回連続で間違えると10分間ロック
  - 実装は `server/auth.js`（DB列は起動時に自動追加）
- **パスキー（生体認証・端末PIN）ログイン**：顔認証・指紋・端末のPIN（Face ID / Touch ID / Windows Hello / Android の生体認証など）でログイン
  - 全員（営業・CS・管理者）が任意で利用可。ログイン後、ヘッダーの 🔐 →「この端末を登録する」で登録（1人で複数端末可）
  - ログイン画面の「🔑 生体認証・パスキーでログイン」から、ID・パスワード・6桁コードなしでログイン
  - 本人確認（顔・指紋・PIN）を必須にしているため、多要素認証を満たす扱い（管理者も6桁コード不要）
  - 生体情報は端末内で照合されるだけで、サーバーには公開鍵のみ保存（`user_passkeys` テーブル、RLS適用）
  - 管理者は「メンバー」画面で各メンバーの登録端末を確認・削除可能（端末紛失時）
  - パスキーは `APP_BASE_URL` のドメインに紐づく。**URL（ドメイン）を変更すると全員の登録し直しが必要**
  - 従来の ID＋パスワード（＋6桁コード）でのログインも引き続き利用可能
- **サーバー側の権限チェック**（2026-11 不具合調査で強化）：画面の表示ルールと同じ権限を、サーバー側でもログイン中の本人情報で判定
  - 営業：自分が担当営業の案件のみ閲覧・修正（備考・関連URLなど）・削除・日程確定・メッセージ可。担当営業・ステータス・CS担当者の変更は不可
  - CS部員：全案件を閲覧・キャンセル可（修正・削除・メッセージは不可）
  - 管理者：全操作。候補日の追加・編集・削除・設定完了、確定後のCS変更、日程確定の催促は管理者のみ
  - メッセージの送信者名・削除の依頼者は、画面から送られた値ではなくログイン情報から決定（なりすまし防止）
  - 状態チェック：キャンセル済み・納品済みの案件は確定・再キャンセル不可、確定済み以降は候補日の変更不可
- **安定性**：処理中のエラーやDBの再起動・通信の瞬断でアプリ全体が停止しないよう、エラーを捕捉して応答（数値欄への文字など不正な入力は400で返す）
- **パスワード変更時の強制ログアウト**：管理者がパスワードを変更すると、変更前のログイン状態は無効になる
- **同じ表示名は登録可能**（方針どおり）。表示名を変更すると担当案件・依頼した案件・候補日のCS担当も自動で付け替え。ただし変更前の表示名を他の人も使っている場合は、どちらの案件か区別できないため付け替えない
  - 注意：案件と担当者は表示名で結び付いているため、同じ表示名の営業どうしは互いの案件が「自分の案件」として表示される。区別が必要な場合は「山田 太郎（東京）」のように表示名を分けて運用する
- **メール本文の無害化**：顧客名やメッセージなどに書かれたHTMLタグは、メール内でただの文字として表示
- **Node.js のバージョン固定**：2026年10月のNode.jsセキュリティ修正（CVE-2026-111497 ほか計10件）を反映した 22.23.4 を `.node-version` で指定（`package.json` の `engines` も修正版以上に限定）。起動時に修正前のバージョンを検知するとログに 🚨 警告を出す
- **多層防御**：Brotli（br）圧縮のリクエスト本文は 415 で拒否／Gmail API の応答は gzip・deflate のみ受け付け
- **ライブラリの脆弱性**：サーバー側は `npm audit` で既知の脆弱性 0 件（2026-10-22時点）。nodemailer を 10.x に更新、uuid は Node 標準の `crypto.randomUUID` に置き換え、googleapis 内部の uuid は `overrides` で修正版に固定
  - 画面側（client）に残る vite / esbuild の指摘は開発用サーバー（`npm run dev`）のみに関係し、本番で配信する画面には影響しない

## 5. デプロイ手順

### Step 1：Supabase でDBを作成

1. https://supabase.com にアクセス → **Start for free** でアカウント作成
2. **New Project** をクリック
3. 任意の名前（例: `delivery-scheduler`）と DB パスワードを設定して作成（2〜3分かかります）
4. 作成後、左メニュー → **Project Settings → Database** を開く
5. **Connection string** → **URI** タブを選択
6. 表示されている接続URL（`postgresql://postgres:...`）をコピー

### Step 2：GitHub にリポジトリを作成／更新

```bash
cd delivery-scheduler
git add .
git commit -m "update"
git push
```

### Step 3：Render.com にデプロイ

1. https://render.com にアクセス → **Start for Free** でアカウント作成（無料・クレカ不要）
2. **New → Web Service** を選択
3. GitHubアカウントを接続して、リポジトリ（`masa31457131/delivery-scheduler`）を選択
4. 以下を設定：

| 項目 | 値 |
|------|----|
| **Name** | delivery-scheduler（任意） |
| **Environment** | Node |
| **Build Command** | `npm run install:all && npm run build` |
| **Start Command** | `npm start` |
| **Instance Type** | **Free** |

5. **Environment Variables** に以下を追加：

| Key | 必須 | 説明 |
|-----|:---:|------|
| `NODE_ENV` | ✅ | `production` |
| `DATABASE_URL` | ✅ | Supabase の接続URL（`postgresql://postgres:パスワード@...`） |
| `SESSION_SECRET` | 推奨 | ログイントークンの署名鍵。ランダムな長い文字列（32文字以上）を設定。未設定時は `DATABASE_URL` から自動生成（動作はするが、設定を推奨） |
| `MFA_ENCRYPTION_KEY` | 推奨 | 認証アプリ用シークレットの暗号化キー。ランダムな長い文字列。**設定後に変更すると既存の多要素認証が使えなくなる（全員リセットが必要）ので、一度決めたら変えないこと** |
| `APP_BASE_URL` | 任意 | メール内リンクのベースURL兼パスキーの紐づけ先（未設定時は `https://delivery-scheduler-c4cd.onrender.com`）。**実際にアクセスするURLと一致させること**（不一致だとパスキーが使えない） |
| `GMAIL_CLIENT_ID` | メール送信に必須 | Google Cloud OAuthクライアント（種類：ウェブアプリケーション） |
| `GMAIL_CLIENT_SECRET` | メール送信に必須 | 同上 |
| `GMAIL_REFRESH_TOKEN` | メール送信に必須 | OAuth Playgroundなどで取得したリフレッシュトークン |
| `GMAIL_SENDER_ADDRESS` | メール送信に必須 | 送信元Gmailアドレス |
| `RESEND_API_KEY` | Resendを使う場合のみ | 独自ドメイン設定済みの場合の代替送信手段 |

> Gmail API用の環境変数が未設定の場合、メール送信はスキップされます（アプリ自体は正常に動作します）。

6. **Create Web Service** をクリック → 自動でビルド・デプロイが始まります（3〜5分）
7. デプロイ完了後、表示されたURLにアクセス！（DBスキーマ・初期データはサーバー起動時に自動作成されます）

## 9. データモデル概要

| テーブル | 概要 |
|---------|------|
| `users` | 管理者・営業・CS部員の全アカウント（`role` で区別、`area` で東京／大阪を管理） |
| `projects` | 案件本体（ステータス・担当営業・CS担当・確定日時など）。関連URLは `client_urls`（`[{url, label}]` のJSON）に保存。旧 `client_url` には互換用に先頭URLを保持 |
| `schedule_candidates` | 案件ごとの候補日（仮スケジュール）。候補日単位で営業メンバー・CS担当者を保持 |
| `blocked_dates` | エリアごとの予定不可日 |
| `settings` | メール送信設定・メール文面テンプレートなど |

## 10. 多要素認証の運用メモ

- **全管理者がスマホを失った場合**（他にリセットできる管理者がいない）：Supabase の SQL Editor で次を実行すると、次回ログイン時に再設定できます。
  ```sql
  UPDATE users SET mfa_enabled=FALSE, mfa_secret=NULL, mfa_backup_codes=NULL, mfa_last_step=NULL,
                   login_fail_count=0, login_locked_until=NULL
  WHERE login_id = '（対象のログインID）';
  ```
- **ロックされた場合**：10分待つか、上記SQLの `login_fail_count=0, login_locked_until=NULL` の部分だけ実行すると解除できます。
